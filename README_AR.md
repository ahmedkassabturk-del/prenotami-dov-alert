# مراقب DOV Only for universities — Prenot@mi

الإصدار 0.1.0 — تنبيه تيليجرام فقط، بدون حجز تلقائي.

## ماذا يفعل؟

- يفتح صفحة Prenot@mi الرسمية بمتصفح Chrome عادي.
- يسجل الدخول بالقيم المحفوظة عندك في GitHub Secrets.
- يبحث فقط عن صف **DOV Only for universities** بالإنجليزية أو الإيطالية.
- يقرأ خلية **Booking** فقط؛ لذلك لا يخلط بين زر الحجز ورابط **Link 1** الموجود في العمود التالي.
- إذا ظهرت **BOOK** أو **PRENOTA**، يرسل تنبيه تيليجرام واحدًا ثم يوقف Workflow تلقائيًا.
- لا يضغط زر الحجز، ولا يختار موعدًا، ولا يحاول تجاوز CAPTCHA أو أي حماية.

الحالة الموجودة في لقطة الشاشة التي أرسلتها هي **غير متاح** لأن خلية Booking تقول: `Booking calendar not yet available`.

## مهم جدًا قبل أي خطوة

كلمة المرور التي كتبتها في المحادثة أصبحت مكشوفة. غيّرها الآن من الموقع، وغيّرها أيضًا في أي حساب آخر إذا كنت تستعمل نفس الكلمة. لا تستخدم الكلمة القديمة داخل هذا المشروع.

شروط Prenot@mi الرسمية تقول إن بيانات الدخول يجب حفظها بعناية ولا تُعطى لغيرك، وتحذر من الحجوزات المتعددة عبر أنظمة آلية. هذا المشروع لا يحجز نهائيًا، لكنه يظل مراقبًا آليًا؛ استخدامه مسؤوليتك. أوقفه فورًا إذا ظهر منع أو تحذير، ولا تحاول تجاوز الحماية.

الشروط الرسمية:
https://prenotami.esteri.it/Content/docs/TERMINI%20E%20CONDIZIONI%20PRENOT%40MI.pdf

## لماذا GitHub Actions؟

هاتف Android قد يوقف البرامج والمتصفح في الخلفية، ولذلك لا يُعتمد عليه للمراقبة طوال اليوم. GitHub Actions يعطي جهاز Linux مؤقتًا على الإنترنت. الاستخدام على Standard Runner في مستودع **عام Public** مجاني حاليًا؛ المستودع الخاص له رصيد دقائق محدود لا يكفي لفحص كل 5 دقائق.

حد GitHub الأدنى للجدولة هو 5 دقائق، وقد يتأخر التشغيل أو يُسقط أحيانًا وقت الضغط. كما تُعطّل الجداول في المستودع العام بعد 60 يومًا دون أي نشاط. إذن التنبيه سريع قدر الإمكان مجانًا، لكنه ليس لحظيًا مضمونًا.

مراجع GitHub الرسمية:

- https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule
- https://docs.github.com/en/billing/concepts/product-billing/github-actions
- https://docs.github.com/en/actions/reference/security/secure-use

## المطلوب

- حساب GitHub مجاني.
- بوت Telegram وتوكنه.
- `chat_id` الخاص بك.
- كلمة مرور Prenot@mi الجديدة.

يمكنك استعمال نفس بوت Telegram و`chat_id` الخاصين بمراقب Almaviva.

## 1) تجهيز بوت Telegram

إذا جهزته سابقًا، انتقل للخطوة التالية.

1. افتح `@BotFather` في Telegram.
2. أرسل `/newbot` واتبع التعليمات، ثم احتفظ بالـToken في مكان آمن.
3. افتح البوت الجديد وأرسل `/start`.
4. للحصول على `chat_id`، افتح مؤقتًا في المتصفح:

   `https://api.telegram.org/botYOUR_TOKEN/getUpdates`

5. ابحث عن `chat` ثم `id`. استخدم نافذة خاصة وأغلقها بعد ذلك لأن الرابط يحتوي على التوكن.

## 2) إنشاء المستودع من هاتف Samsung

1. افتح https://github.com/new وسجل الدخول.
2. اكتب اسمًا مثل `prenotami-dov-alert`.
3. اختر **Public** لكي تظل الدقائق مجانية، ثم اضغط **Create repository**.
4. لا تضف أي شخص بصلاحية Write إلى المستودع.

الكود سيكون عامًا، لكن الأسرار التالية ستظل في إعدادات حسابك وليست داخل الكود.

## 3) إضافة الأسرار الأربعة

من صفحة المستودع افتح:

**Settings → Secrets and variables → Actions → New repository secret**

أضف الأسماء التالية حرفيًا:

| الاسم | القيمة |
| --- | --- |
| `PRENOTAMI_EMAIL` | بريد حساب Prenot@mi |
| `PRENOTAMI_PASSWORD` | كلمة المرور الجديدة، وليس التي ظهرت في المحادثة |
| `TELEGRAM_BOT_TOKEN` | توكن BotFather |
| `TELEGRAM_CHAT_ID` | رقم chat_id |

لا تضع علامات اقتباس حول القيم. قد تحتاج من متصفح الهاتف إلى تفعيل **Desktop site** لرؤية Settings بسهولة.

## 4) رفع الملفات من الهاتف

فك ضغط الملف ثم ارفع هذه العناصر إلى جذر المستودع:

- `monitor.py`
- `detector.py`
- `requirements.txt`
- مجلد `tests`
- `README_AR.md` و`SECURITY_AR.md` (اختياريان للتشغيل لكن يُفضل رفعهما)

ثم أنشئ ملف Workflow:

1. في GitHub اضغط **Add file → Create new file**.
2. في اسم الملف اكتب بالضبط: `.github/workflows/check-dov.yml`
3. افتح الملف `MOBILE_WORKFLOW_COPY.yml` من الحزمة، وانسخ محتواه كله والصقه.
4. اضغط **Commit changes** إلى الفرع `main`.

إذا أظهر تطبيق الملفات المجلد المخفي `.github` واستطعت رفعه كما هو، فلن تحتاج خطوة النسخ اليدوي. الملف `MOBILE_WORKFLOW_COPY.yml` مجرد نسخة مساعدة ولا يعمل من جذر المستودع.

## 5) اختبار تيليجرام

1. افتح تبويب **Actions** في المستودع.
2. اختر **Prenotami DOV monitor**.
3. اضغط **Run workflow**.
4. فعّل **Send a Telegram test only** ثم شغّل.

يجب أن تصلك رسالة اختبار. وضع الاختبار لا يفتح Prenot@mi ولا يحتاج البريد أو كلمة المرور.

## 6) اختبار الموقع وتشغيل المراقبة

شغّل Workflow يدويًا مرة ثانية مع ترك اختبار Telegram مغلقًا:

- إذا كان التقويم غير متاح: ينتهي التشغيل باللون الأخضر ولا يرسل رسالة.
- إذا أصبح متاحًا: يرسل الرسالة ويوقف Workflow تلقائيًا بعد أول تنبيه.
- إذا تغيرت الصفحة أو ظهر منع آلي: يفشل التشغيل باللون الأحمر ولا يحاول التحايل.

بعد رفع Workflow، الجدول يبدأ تلقائيًا كل 5 دقائق تقريبًا. لا يلزم ترك الهاتف مفتوحًا.

## بعد وصول التنبيه

افتح Prenot@mi واحجز بنفسك. إذا لم تلحق الموعد وتريد تشغيل المراقبة مرة أخرى:

**Actions → Prenotami DOV monitor → Enable workflow**

## إيقاف أو حذف البوت

- إيقاف مؤقت: **Actions → Prenotami DOV monitor → Disable workflow**.
- إيقاف نهائي: احذف المستودع من **Settings → Danger Zone**، ثم احذف الأسرار أو غيّرها إن لزم.

## حدود متوقعة

- لا يوجد ضمان أن GitHub سيبدأ كل تشغيل في الثانية المحددة.
- قد يمنع Prenot@mi عناوين مراكز البيانات أو يغير صفحة الدخول/الجدول. الكود يتوقف في هذه الحالة ولا يتجاوز الحماية.
- كثرة تسجيل الدخول قد تثير حماية الموقع. استخدمه لفترة الحاجة فقط، وأوقفه إذا ظهرت مشكلة بالحساب.
- لا ينفذ المشروع حجزًا تلقائيًا عمدًا لحماية الحساب وتقليل المخاطر.
